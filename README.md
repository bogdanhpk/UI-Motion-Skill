# UI Motion

Один скилл для анимации и полировки интерфейсов: интерактивные переходы, поверхности и иконки, анимация готовых макетов, продуктовые демо и SwiftUI.

Внутри объединены `animate`, `better-ui`, `design-to-motion`, `stageshow` и `swiftui-animation-match`. Основные инструкции находятся в [ui-motion/SKILL.md](ui-motion/SKILL.md); подробные справочники загружаются по задаче.

Скилл сохраняет компоненты и токены проекта. Для Koobiq он использует штатные компоненты, тему, типографику и иконки. Принципы Apple, Material, Fluent и Carbon собраны со ссылками на первоисточники в [правилах анимации](ui-motion/references/motion-principles.md).

## Установка

В Codex попросите `$skill-installer` установить скилл из:

```text
https://github.com/bogdanhpk/UI-Motion-Skill/tree/v1.0.0/ui-motion
```

Или запустите штатный установщик:

```sh
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo bogdanhpk/UI-Motion-Skill --path ui-motion --ref v1.0.0
```

Установщик останавливается, если `ui-motion` уже существует. Такая установка создаёт копию конкретной версии; сама по себе она не включает автообновление. Скилл будет доступен на следующем ходе Codex. Для явного вызова используйте `$ui-motion`.

## Обновления

Стабильные версии публикуются в [GitHub Releases](https://github.com/bogdanhpk/UI-Motion-Skill/releases). Версия `vX.Y.Z` соответствует `VERSION` и `metadata.version` скилла. Черновики и предварительные релизы не входят в стабильный канал.

Для отслеживания версий можно хранить отдельный клон репозитория и подключить каталог `ui-motion` символической ссылкой в `~/.codex/skills`. Автоматизацию в Codex нужно создать отдельно: проверять последний стабильный Release, обновляться только на более новую версию и сохранять текущую при локальных изменениях или ошибке проверки. GitHub сам не меняет файлы на компьютере.

На компьютере автора настроена такая проверка раз в час. Она проверяет origin, чистоту клона, соответствие версии тегу и целостность скилла перед переключением. Изменения в `main` не устанавливаются до выпуска стабильного релиза. Работа расписания зависит от доступности локальной среды Codex и сети.

## Проверка

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/validate_skill.py
```

Проверка охватывает метаданные, согласованность версии, обязательные файлы, внутренние ссылки и отсутствие символических ссылок внутри пакета. Она не заменяет проверку самой анимации в работающем интерфейсе.

## Выпуск новой версии

1. Внесите изменения в `ui-motion/`.
2. Обновите `VERSION`, `metadata.version` в `SKILL.md` и `CHANGELOG.md`.
3. Выполните проверку и отправьте коммит в `main`.
4. Создайте и отправьте соответствующий тег:

```sh
git tag v1.0.1
git push origin v1.0.1
```

GitHub Actions проверит пакет и создаст стабильный Release. После публикации локальная автоматизация сможет установить его на ближайшей проверке. Опубликованные теги сохраняйте неизменными; исправления выпускайте следующей версией.
